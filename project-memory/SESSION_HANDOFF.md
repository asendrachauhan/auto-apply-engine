## 1. THE COMPLETE GOAL

**AutoApply AI** is a production SaaS job-application automation platform.
Stack: Angular 17+ frontend, Node/Express/MongoDB backend, Groq for AI,
Stripe for billing, Resend for email, Twilio for WhatsApp.

**Target audience (current, explicit):** Job seekers in India, across
EVERY job category — technical, marketing, sales, BPO/voice process,
support, any field. This was explicitly broadened from an original
tech-only bias (Sessions 42-43 — see section 2). International expansion
beyond India (USA, wider Europe, etc.) was requested once, then explicitly
deferred by Asendra in favor of getting India right first — do not start
building multi-region support unless she asks again specifically.

**Core product differentiators:**
- **Ghost Job Detection** — scores every job listing 0-100 for legitimacy
  before showing it to the user (rule-based heuristics: ATS platform URLs,
  posting age, etc. — not an AI prompt, see `ghostJob.service.js`).
- **Explainable AI match scores** — not just "82% match," but WHY, with
  reasons and missing-skill gaps, generated by Groq.
- **India→Europe career intelligence** — CTC-to-EUR salary conversion,
  visa pathway guidance. NOTE: this specific module
  (`indiaToEurope.service.js`) is IT-salary-specific BY DESIGN (its salary
  benchmarks are IT market data) and was NOT broadened alongside the rest
  of the app in Sessions 42-43 — see section 3 for why, and section 6 for
  the open question this leaves.

**What the product actually does for a user:** upload/parse resume →
AI-optimize it → discover jobs from 8 sources across two pipelines
(auto-apply-eligible: Remotive/Himalayas/Adzuna/Arbeitnow; alert-only:
those 4 plus Indeed/Google Jobs/LinkedIn/Naukri, the last two paid-plan-
gated) → ghost-score and AI-match every listing → generate a cover letter
and application prefill packet → either auto-apply (with a daily cap by
plan, human review encouraged) or let the user apply manually from an
alert. Plus: referral program, admin control panel (real payments/
referrals kill-switches, Stripe coupon generation), GDPR-compliant data
export/deletion, multi-device session management.

**Business model:** Free / Starter / Pro / Elite plans, gated by daily
apply limit, job source access, and real-time watching. The admin panel
can flip a global "Payments" toggle that makes the ENTIRE product free for
everyone (real backend enforcement, not just hiding UI) — built for
promotional/launch flexibility.

## SESSION 62 UPDATE — AI MODEL MIGRATION, RATE LIMIT DECOUPLING & JOB DISCOVERY (2026-09-27)

### 1. Root Cause Analysis & Complete Fixes:
1. **Groq Model Token Exhaustion**:
   - `openai/gpt-oss-120b` was consuming 1,500+ hidden reasoning tokens (`completion_tokens_details.reasoning_tokens`) per call, hitting Groq's 8,000 TPM limit in 1-2 prompts.
   - Migrated to `qwen/qwen3.8-27b`: 0 hidden reasoning tokens, blazing fast (~500ms), 32k context, high structured JSON accuracy.
   - Built automatic cross-model failover in `groq.service.js`: if `qwen/qwen3.8-27b` hits 429 (e.g. 1,000 OTPM quota), it automatically fails over to `openai/gpt-oss-20b` (8,000 TPM limit with no OTPM ceiling), doubling free tier capacity.
2. **AI Failure Decoupling (Fixing Broken Login)**:
   - Root cause: `process.on('unhandledRejection', () => process.exit(1))` in `app.js` killed the entire Express server whenever background AI scrapers or job watchers hit 429 rate limits. This caused frontend requests (like `/api/auth/login`) to fail with `ERR_CONNECTION_REFUSED`.
   - Removed `process.exit(1)` from `unhandledRejection` so background rate limits never crash the Node process.
   - Login, dashboard navigation, subscriptions, and non-AI features now remain 100% operational regardless of Groq token status.
3. **Critical Server Error Email Spam**:
   - Winston logger's email alert transport was triggering `sendCriticalAlert` on every `logger.error` call, flooding user's Gmail on 429 rate limits.
   - Downgraded 429 and transient Groq errors to `logger.warn` and added regex filters in `alertMailer.js` to suppress rate limits and JSON validation errors from triggering emergency admin emails.
4. **Naukri & Indeed Job Discovery Restoration**:
   - Both portals retired legacy public RSS feeds.
   - Replaced/supplemented with SerpApi Google Jobs targeted fallback for Indeed and Google search fallback for Naukri with persistent caching (`SerpApiCache`).
   - Fixed `jobDiscovery.service.js` to pick the first physical city when candidate preferences include `"Remote"`.
   - Expanded Indian region matching in `jobEligibility.js` to include Indian states (Maharashtra, Karnataka, etc.).
   - Calibrated heuristic scoring in `jobMatcher.service.js` (+35 base title boost) so matching Naukri/Indeed postings consistently pass the 65% threshold.
   - Verified live execution: 215 jobs discovered across platforms, including 23 from Naukri and 2 from Indeed, with live alerts generated in MongoDB Atlas.
5. **Test Suite Status**:
   - 100% passing: all 34 backend test suites and all 325 tests pass cleanly (`npm test -- --no-coverage --forceExit`).
   - Frontend compiles cleanly (`tsc --noEmit`).
